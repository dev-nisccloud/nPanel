# Payment Gateway Integration

This folder contains payment gateway integrations for the npanel application.

## Current Integrations

### M-Pesa (Kenya)

M-Pesa STK Push integration for processing mobile money payments in Kenya.

### Jenga Payment Gateway (Card Payments)

Jenga Payment Gateway integration for secure card payment processing. Supports Visa, Mastercard, AMEX, Union Pay, JCB, and Diners Club cards with 3D Secure authentication. [See full documentation →](./JENGA-CARDS.md)

**Live wiring (implemented):**
- tRPC: `paymentGateway.jenga.initiateCardPayment` / `getPaymentStatus`
- Storefront: `storefront.payment.initiateJengaCheckout` / `getJengaPaymentStatus`
- Webhooks: `GET /api/webhooks/jenga/callback`, `POST /api/webhooks/jenga/ipn` (Basic Auth)
- Dashboard return: `/payment/jenga/return` → `niscServiceOrders.createFromJengaPayment`
- UI: Card method on buy-now, global buy-now, and storefront cart payment dialog

**Env template:** [jenga/.env.jenga.example](./jenga/.env.jenga.example)

## Setup

### Environment Variables

Add the following environment variables to your `.env` file:

```env
# M-Pesa Configuration
MPESA_ENVIRONMENT=sandbox  # or "live" for production
MPESA_CONSUMER_KEY=your_consumer_key
MPESA_CONSUMER_SECRET=your_consumer_secret
MPESA_SHORTCODE=your_shortcode
MPESA_PASSKEY=your_passkey
MPESA_PARTY_B=your_party_b
MPESA_TRANSACTION_TYPE=CustomerPayBillOnline  # or "CustomerBuyGoodsOnline" for Buy Goods/Tills
MPESA_CALLBACK_URL=https://yourdomain.com/api/webhooks/mpesa

# Note: MPESA_ACCOUNT_REFERENCE is NOT required in env variables.
# The accountReference must be provided per transaction in the request body.
# It should be generated by the calling service (e.g., order number, invoice number, domain name).
# Format: {protocol}://{domain}/api/webhooks/mpesa
# Examples:
#   Development: http://localhost:3000/api/webhooks/mpesa
#   Production: https://yourdomain.com/api/webhooks/mpesa
#   Staging: https://staging.yourdomain.com/api/webhooks/mpesa
# Note: M-Pesa requires HTTPS in production. The domain must be publicly accessible.

# Optional: IP Whitelist (comma-separated)
# For production, configure this at your load balancer/firewall level
MPESA_ALLOWED_IPS=196.201.214.18,196.201.214.19,196.201.214.20
```

### Getting M-Pesa Credentials

1. **Sandbox Environment:**
   - Register at [Safaricom Developer Portal](https://developer.safaricom.co.ke/)
   - Create an app to get Consumer Key and Consumer Secret
   - Use test credentials provided in the portal

2. **Live Environment:**
   - Complete the onboarding process with Safaricom
   - Get your production credentials from Safaricom
   - Set up your callback URL (must be HTTPS in production)

## Usage

### Initiate STK Push Payment

```typescript
import { trpc } from "@/utils/trpc";

const initiatePayment = trpc.paymentGateway.mpesa.initiateStkPush.useMutation();

// Call the mutation
initiatePayment.mutate({
  phoneNumber: "0712345678", // or "254712345678"
  amount: 100, // Amount in KES (minimum 1)
  accountReference: "ORDER-123", // REQUIRED - Max 12 characters, alphanumeric only
  transactionDesc: "Payment", // Optional - Max 13 characters
  callbackUrl: "https://custom-callback.com/webhook", // Optional, uses default from env
  teamId: "team-id-123", // Optional, for team payments
});
```

### Query Payment Status

```typescript
const queryPayment = trpc.paymentGateway.mpesa.queryStkPush.useQuery({
  checkoutRequestId: "checkout_request_id_from_initiate_response",
});
```

## Validation Rules

### Request Parameters

- **phoneNumber**: Minimum 10 digits, automatically formatted to 254XXXXXXXXX format
- **amount**: Must be positive, minimum 1 KES
- **accountReference**: 
  - Required
  - Maximum 12 characters
  - Alphanumeric only (a-z, A-Z, 0-9)
  - Examples: "ORDER-123", "INV-456", "DOMAIN-COM"
- **transactionDesc**: 
  - Optional
  - Maximum 13 characters
  - Examples: "Payment", "Domain reg"
- **callbackUrl**: 
  - Optional
  - Must be a valid URL
  - Defaults to `MPESA_CALLBACK_URL` from environment

### Transaction Type

The `MPESA_TRANSACTION_TYPE` environment variable determines the type of M-Pesa transaction:

- **CustomerPayBillOnline**: Use for Pay Bill transactions (default for most businesses)
  - Use when `MPESA_PARTY_B` is a Pay Bill number
  - Example: `MPESA_TRANSACTION_TYPE=CustomerPayBillOnline`

- **CustomerBuyGoodsOnline**: Use for Buy Goods/Till Number transactions
  - Use when `MPESA_PARTY_B` is a Till Number
  - Example: `MPESA_TRANSACTION_TYPE=CustomerBuyGoodsOnline`

**Important:** The transaction type must match your `MPESA_PARTY_B` value:
- If `MPESA_PARTY_B` is a Pay Bill number → Use `CustomerPayBillOnline`
- If `MPESA_PARTY_B` is a Till Number → Use `CustomerBuyGoodsOnline`

## Error Handling

The gateway includes comprehensive error handling based on official M-Pesa API error codes:

### Common Error Codes

- **400.002.02**: Bad Request – Invalid parameter
- **404.001.03**: Invalid Access Token (retryable)
- **404.001.01**: Resource not found
- **405.001**: Method Not Allowed
- **500.001.1001**: Merchant does not exist / Wrong credentials / Unable to lock subscriber (retryable after 60s)
- **500.003.02**: System is busy / Spike Arrest Violation (retryable after 30s)
- **500.003.1001**: Internal Server Error (retryable after 10s)
- **500.003.03**: Quota Violation (retryable after 60s)

### Result Codes (Callback)

- **0**: Success
- **1**: Insufficient balance
- **2**: Amount below minimum (Ksh 1)
- **3**: Amount exceeds maximum
- **4**: Would exceed daily transfer limit (Ksh 500,000)
- **17**: Rule limited (wait 2 minutes between similar requests)
- **1032**: Request cancelled by user
- **1037**: User cannot be reached
- **2001**: Incorrect M-PESA PIN

All errors are logged with full details including error codes, descriptions, and mitigation strategies.

## Security Features

### Implemented Security Measures

1. **Authentication Required**
   - All endpoints require authenticated user sessions
   - Uses `protectedProcedure` from tRPC

2. **Input Validation**
   - All inputs validated using Zod schemas
   - Phone numbers sanitized and formatted
   - Amount validation (positive numbers only, minimum 1)
   - Account reference validation (max 12 chars, alphanumeric)
   - Transaction description validation (max 13 chars)

3. **No Hardcoded Credentials**
   - All credentials from environment variables
   - Credentials validated at startup

4. **Webhook Security**
   - IP whitelist validation (configurable)
   - Payload structure validation
   - Request origin logging
   - Always returns success to prevent M-Pesa retries

5. **Error Handling**
   - Generic error messages to users
   - Detailed logging for debugging
   - No sensitive data in error responses

### Additional Security Recommendations

1. **Rate Limiting**
   - Implement rate limiting at the API gateway/load balancer level
   - Limit requests per user/IP to prevent abuse

2. **IP Whitelisting**
   - Configure M-Pesa IP whitelist at infrastructure level (firewall/load balancer)
   - M-Pesa IP ranges:
     - Sandbox: `196.201.214.0/24`
     - Live: `196.201.214.0/24`, `196.201.214.18`, `196.201.214.19`, `196.201.214.20`

3. **HTTPS Only**
   - Always use HTTPS in production
   - M-Pesa requires HTTPS for callback URLs in production

4. **Monitoring & Logging**
   - Monitor all payment transactions
   - Log all webhook callbacks for audit trail
   - Set up alerts for failed payments

5. **Database Security**
   - Store payment records securely
   - Encrypt sensitive payment data at rest
   - Implement proper access controls

6. **Callback URL Validation**
   - Validate callback URLs are from your domain
   - Use signed URLs or tokens for additional security

## Webhook Handler

The webhook handler is located at:
- **Route:** `/api/webhooks/mpesa`
- **File:** `apps/npanel/src/app/api/webhooks/mpesa/route.ts`

### Webhook Payload Structure

M-Pesa sends callbacks in this format:

```json
{
  "Body": {
    "stkCallback": {
      "MerchantRequestID": "string",
      "CheckoutRequestID": "string",
      "ResultCode": 0, // 0 = success, non-zero = failure
      "ResultDesc": "string",
      "CallbackMetadata": {
        "Item": [
          {
            "Name": "Amount",
            "Value": 100
          },
          {
            "Name": "MpesaReceiptNumber",
            "Value": "receipt_number"
          },
          {
            "Name": "TransactionDate",
            "Value": "20240101120000"
          },
          {
            "Name": "PhoneNumber",
            "Value": "254712345678"
          }
        ]
      }
    }
  }
}
```

### Processing Webhooks

The webhook handler:
1. Validates the request origin (IP whitelist)
2. Validates the payload structure
3. Extracts payment information
4. Updates your database/order system
5. Sends notifications to users

**Important:** Always return success to M-Pesa to prevent retries. Process errors asynchronously.

## Common Issues

### "Invalid phone number format"
- Ensure phone number is in format: `0712345678` or `254712345678`
- The system automatically formats phone numbers

### "Access token error"
- Check your Consumer Key and Consumer Secret
- Verify environment variables are set correctly
- Check if token cache is working

### "Webhook not received"
- Verify callback URL is accessible (HTTPS in production)
- Check firewall/load balancer settings
- Verify IP whitelist configuration
- Check application logs for errors

### "Payment failed"
- Check M-Pesa account balance
- Verify shortcode and passkey are correct
- Check transaction limits
- Review M-Pesa API response for specific error
