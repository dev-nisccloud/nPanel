## What was done

### Currency and checkout

- **Currency follows location.** The website picks the currency from the visitor's country. Kenya and undetected locations get KES; every other recognised country gets USD. Country comes only from trusted CDN headers (`cf-ipcountry`, `x-vercel-ip-country`, `cloudfront-viewer-country`). Code: `packages/location`, `packages/api/src/routers/storefront/location.ts`, `apps/www.nisccloud.com/src/components/providers/currency.tsx`.
- **The navbar currency selector was removed** at the owner's request (desktop and mobile). Saved browser or account currency choices no longer override location on the website.
- **USD falls back to KES quietly.** If the exchange rate cannot load, prices are shown in genuine KES rather than an error, and checkout stays available. KES amounts are never relabelled as USD.
- **Exchange rate:** `packages/api/src/lib/fx-rates.ts` uses ExchangeRate-API (keyed if `EXCHANGERATE_API_KEY` is set), cached in Redis for up to 6 hours. Tested locally: 1 USD ≈ KES 130.
- **Server-side quotes:** signed 15-minute quotes lock the cart, totals, FX snapshot and tax policy. The payment dialog uses a snapshot taken when it opens, so a currency change cannot alter a payment in progress (`apps/www.nisccloud.com/src/pages/cart/page.tsx`).
- **Payments:** M-Pesa and Jenga settlement now require server verification and exact amount matching. Paystack is built (backend initialisation, InlineJS, signed webhooks, server verification, replay protection) but is behind feature flags and off.
- **Records:** orders, payments and invoices store currency, FX, KES fiscal equivalent and tax evidence (migrations `0072`–`0073`). Default VAT is 16%; foreign zero-rating and foreign-currency eTIMS submission are disabled.
- **Saved preference (nPanel):** migration `0074`, `user.getDisplayCurrencyPreference` / `updateDisplayCurrencyPreference`, storefront equivalents, and a KES/USD setting on nPanel's account settings page. The website no longer reads this preference; see "Decisions needed".

## Running it locally

The local website proxies all `/api` calls to the live server by default (`VITE_NPANEL_SERVER_URL`). To test the new location and exchange-rate endpoints before deployment:

```powershell
# Terminal 1 — API server on port 8050 (apps/server/.env points at a local database on 127.0.0.1:54322)
cd apps/server
bun run dev

# Terminal 2 — website, sending only storefront.location.* to the local API
cd apps/www.nisccloud.com
$env:DEV_LOCATION_API_URL='http://127.0.0.1:8050'
$env:DEV_SIMULATE_COUNTRY='US'   # omit to behave as a Kenyan/unknown visitor
bun run dev
```

These two variables only affect the Vite dev server. Plans, cart and checkout still come from the live server unless the local database is running (Docker Desktop was off during testing).
